Stop sensitive data from reaching LLM APIs

CADLP is an open-source, research-grade proxy layer that intercepts prompts sent to large language model APIs and detects, classifies, and redacts sensitive enterprise data before it leaves the organization. Four-stage detection pipeline, zero-retention audit logging, utility-preserving redaction.

Why this matters

Shadow AI is the defining enterprise data risk of the current decade: employees using consumer LLM tools inadvertently expose credentials, PII, proprietary code, and internal operational context that organizations have no visibility into once it leaves the network boundary. CADLP closes that gap without blocking the productivity gains of AI.

  • Closes the Shadow AI exposure gap. A transparent proxy layer requires no change to employee workflow while intercepting every outbound prompt for sensitivity analysis, giving security teams visibility and control they cannot get from access policies alone.
  • Detects what regex alone misses. The four-stage pipeline escalates from fast regex and entropy detection to NER disambiguation, AST-based code IP fingerprinting, and TF-IDF semantic similarity, catching internal terminology and proprietary logic that pattern-matching cannot identify.
  • Preserves LLM utility after redaction. Typed, indexed placeholders ([EMAIL_1], [API_KEY_1], [PERSON_A]) replace sensitive spans while preserving prompt structure and referential consistency across multi-turn sessions, so redacted prompts still produce useful model outputs.
  • Operationally aware disambiguation. Entities in hypothetical examples are suppressed; entities in action-verb contexts are escalated. This cuts false positives on training data and documentation while maintaining recall on live operational prompts.
  • Audit-log safe by design. Only metadata is logged (entity types, action taken, timestamp); raw prompt content is never persisted, satisfying zero-retention requirements without sacrificing incident traceability.
  • Open and independently verifiable. Apache 2.0-licensed reference implementation, 90 tests, and a SEPAD-10K sample benchmark are public so detection and redaction claims can be independently reproduced.

How it works

The Contextual Sensitivity Classifier (CSC) runs four stages in sequence. Each stage emits a SensitivityMap that drives the Policy Engine, which selects ALLOW, REDACT, BLOCK, or QUARANTINE before the prompt reaches the LLM API.

Stage 1 — Regex + Entropy (fast path)

High-confidence structured secrets: API keys, private keys, JWT tokens, SSNs, credit card numbers, email addresses, and high-entropy opaque strings. Handles 70-80% of sensitive prompts with sub-millisecond latency.

Stage 2 — NER + Disambiguation

Named entity recognition with operational vs. exemplary disambiguation: entities appearing in hypothetical examples or documentation contexts are suppressed; entities in action-verb or imperative contexts are escalated. Catches person names, org codes, and ticket IDs that Stage 1 misses.

Stage 3 — AST Code IP Fingerprinting

Parses code blocks embedded in prompts, analyzes import graphs and identifier naming patterns against an internal symbol corpus, and flags proprietary code fragments. Catches IP leakage that neither regex nor NER can detect.

Stage 4 — Semantic / KB Similarity

TF-IDF cosine similarity against an internal terminology knowledge base identifies domain-specific jargon and internal project codenames that appear innocuous to general NER models but carry confidential meaning in context.

Quick start

Python 3.9+ required.

pip install cadlp

# or with semantic similarity support
pip install "cadlp[full]"

# Scan a prompt from stdin
echo "My API key is sk-abc123XYZ..." | cadlp scan

# Run the built-in demo
cadlp demo

# Run evaluation on the SEPAD-10K sample
cadlp eval --dataset data/sepad10k/sample.json
